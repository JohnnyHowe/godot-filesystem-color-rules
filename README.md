# Filesystem Color Rules

Filesystem Color Rules is a Godot editor plugin that assigns colors to folders in the FileSystem dock using regular-expression rules.

## Setup

Enable **Filesystem Color Rules** in **Project > Project Settings > Plugins**.

Create a `FileSystemColorRules` resource at:

```text
res://filesystem_color_rules.tres
```

Add entries to its `rules` dictionary. Each key is a regular expression and each value is one of the supported folder colors.

## Path Matching

Rules are matched against complete Godot resource folder paths. Paths:

- Start with `res://`.
- Use forward slashes on every platform.
- End with a trailing slash.

For example:

```text
res://addons/filesystem_color_rules/
```

Rules are case-sensitive unless the regular expression enables case-insensitive matching.

### Examples

Match folders named `tests` and everything beneath them:

```regex
.*/tests/.*
```

Match a final folder name containing an uppercase ASCII letter:

```regex
.*/[^/]*[A-Z][^/]*/$
```

Match a final folder name containing `debug`, without matching folders solely because a parent contains `debug`:

```regex
.*/[^/]*debug[^/]*/$
```

Use `(?i)` at the beginning of a pattern for case-insensitive matching.

## Rule Precedence

Rules are evaluated in dictionary order. When a folder matches multiple rules, the last matching rule wins. Put broad rules first and specific overrides later.

## Supported Colors

- Red
- Orange
- Yellow
- Green
- Teal
- Blue
- Purple
- Pink
- Gray

## Updating

The plugin synchronizes colors when the editor filesystem changes and when the rules resource is edited. It requests a FileSystem dock refresh after saving changed assignments.

The plugin has partial ownership of `file_customization/folder_colors`:

- Colors generated by rules are tracked by the plugin.
- Manual folder colors that are not owned by the plugin are preserved.
- When a rule stops matching, its previously generated colors are removed.
